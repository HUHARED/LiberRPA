# Getting Started

This guide covers the shortest path from opening LiberRPA Editor to running and debugging your first Flow Project.

By the end, you will have:

- created a Flow Project;
- added a Python Block to the Flowchart;
- run the Project;
- debugged Python code with VS Code;
- inserted a LiberRPA Snippet.

For installation, offline preparation, portability, and uninstallation, see [Installation, Portability & Uninstallation](./Installation.md).

## Before You Start

This guide assumes that you have already:

1. downloaded and extracted the official LiberRPA release;
2. run `InitLiberRPA.exe`;
3. opened the bundled Editor at least once and allowed the required VS Code extensions to finish installing.

Open LiberRPA Editor with:

```text
<LiberRPA root>\Editor\Code.exe
```

The bundled Editor is configured to use the standard LiberRPA Python environment automatically.

## 1. Create a Flow Project

Open the VS Code Command Palette:

```text
Ctrl+Shift+P
```

Run:

```text
LiberRPA: Create a New Project
```

Then:

1. Select the parent folder where the new Project should be created.
2. Select **Flow Project** and the **Minimalist** template.
3. Enter the required Project information.
4. Review the settings and click **Confirm**.

The new Project opens in a separate LiberRPA Editor window.

For all Project creation options, see [LiberRPA Project Manager](../vscodeExtensions/liberrpa-project-manager/README.md).

## 2. Open the Flowchart

Open:

```text
project.flow
```

from the Project root.

A new Flow Project starts with a single **Start** node.

The Flowchart represents high-level process structure. Detailed implementation logic belongs in Python files used by Block nodes.

> **Visualize the process. Code the logic.**

## 3. Add Your First Block

Drag a **Block** node from the Node Panel onto the Flowchart.

Configure a description such as:

```text
Hello LiberRPA
```

and set its Python file path to:

```text
HelloLiberRPA.py
```

Connect the **Start** node to the Block.

Your Flow should now be conceptually equivalent to:

```text
Start
  │
  ▼
Hello LiberRPA
```

### Create the Block Python file

Click the file-open button in the Block.

If the configured Python file does not exist, LiberRPA creates it automatically. For `HelloLiberRPA.py`, the generated file is:

```python
# FileName: HelloLiberRPA.py
# <LiberRPA imports: managed>
# This block is managed by LiberRPA. Do not edit it manually.
# ruff: isort: off
# ruff: isort: on
# </LiberRPA imports: managed>


def main() -> None:
    raise NotImplementedError()


if __name__ == "__main__":
    main()
```

Keep the generated structure and replace:

```python
raise NotImplementedError()
```

with your implementation:

```python
def main() -> None:
    message = "Hello from LiberRPA"
    print(message)
```

The final file should still retain the managed import block and the `if __name__ == "__main__":` entry point generated by LiberRPA.

Save the file.

> If a Block points to a Python file that does not exist, running the Block or Flow does not create the file automatically. Create it manually or use the Block's file-open button first.

### No End node is required for this example

A node with no outgoing line ends that process after the node completes.

The two-node Flow is therefore sufficient for the first example.

## 4. Run the Project

Return to `project.flow` and make sure the Flowchart is the active editor.

### Run without debugging

Press:

```text
Ctrl+F5
```

LiberRPA runs the complete Flow Project without attaching the Python debugger.

The Block should print:

```text
Hello from LiberRPA
```

and the process should then finish.

### Run from the Start node

You can also click the execution button inside the **Start** node.

The button follows the Flowchart **Execute Mode** setting. The default Flow Project template starts in **Debug** mode.

### Run only one Block

Each Block has its own execution button.

Use it to run only that Block while developing or testing an individual part of a larger Flow.

## 5. Debug the Project

Open `HelloLiberRPA.py` and place a breakpoint on:

```python
print(message)
```

Return to `project.flow` and press:

```text
F5
```

LiberRPA starts the complete Flow Project with the standard Python debugger.

When execution reaches the breakpoint, normal VS Code debugging features are available, including:

- stepping through Python code;
- inspecting variables;
- evaluating expressions;
- viewing the call stack;
- adding additional breakpoints.

For example, inspect `message` and confirm that its value is:

```text
Hello from LiberRPA
```

### Flowchart shortcuts depend on the active editor

When `project.flow` is active:

```text
F5
```

debugs the complete Flow Project, while:

```text
Ctrl+F5
```

runs it without debugging.

When a normal Python file is active, VS Code retains its normal Python shortcut behavior.

For advanced Flow behavior, including Exception Lines, subprocess entry points, Project arguments, recording, and Flow settings, see [LiberRPA Flowchart](../vscodeExtensions/liberrpa-flowchart/README.md).

## 6. Insert a LiberRPA Snippet

Open **LiberRPA Snippets Tree** in the Editor.

Snippets can be inserted by:

- clicking a Snippet in the tree;
- dragging it into a Python editor;
- selecting it through VS Code IntelliSense.

For a simple example, locate the `delay` Snippet and insert it inside `main()`.

When a Snippet requires a LiberRPA import, Snippets Tree updates the managed import block automatically.

For example:

```python
# <LiberRPA imports: managed>
# This block is managed by LiberRPA. Do not edit it manually.
# ruff: isort: off
from liberrpa.Modules import (
    delay,
)
# ruff: isort: on
# </LiberRPA imports: managed>
```

Do not manually edit code inside the managed import block.

Your function can then contain both ordinary Python and LiberRPA APIs:

```python
def main() -> None:
    message = "Hello from LiberRPA"
    print(message)

    delay(1000)

    print("Finished")
```

Run the Block or complete Flow again.

The Snippet helps discover and insert the API, but the resulting implementation remains normal Python source.

For details, see [LiberRPA Snippets Tree](../vscodeExtensions/liberrpa-snippets-tree/README.md).

## 7. The Basic Development Loop

The basic LiberRPA development workflow is:

```text
Design the high-level process in Flowchart
                  │
                  ▼
Write implementation logic in Python
                  │
                  ▼
Run an individual Block while developing
                  │
                  ▼
Run or debug the complete Flow
                  │
                  ▼
Inspect results and logs
                  │
                  ▼
Modify and repeat
```

The same model continues to work as a Project becomes larger: the Flowchart remains focused on process structure while Python files contain detailed implementation logic.

## Quick Reference

| Task                      | Action                                                   |
| ------------------------- | -------------------------------------------------------- |
| Create a Project          | `Ctrl+Shift+P` → `LiberRPA: Create a New Project`   |
| Run the complete Flow     | Open `project.flow` → `Ctrl+F5`                     |
| Debug the complete Flow   | Open `project.flow` → `F5`                          |
| Run from a Flowchart node | Use the node execution button                            |
| Open or create Block code | Use the Block file-open button                           |
| Stop a running Flow       | `Ctrl+F12` when the Flowchart Stop Shortcut is enabled |
| Insert an automation API  | Snippets Tree, drag and drop, or IntelliSense            |

1. Run `LiberRPA: Package Project`.

4. Review and save the local Run Settings.
