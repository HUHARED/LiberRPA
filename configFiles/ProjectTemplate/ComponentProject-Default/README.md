# LiberRPA Component Project

## Introduction

This is a LiberRPA Component Project.

A Component is a reusable Python package containing one or more public modules. Each module can provide functions for Flow Projects or other Components.

## Component identity

The Component identity is stored in `component.json`.

Important fields include:

* `id`: The stable Component ID generated by LiberRPA Project Manager.
* `packageName`: The top-level Python package name.
* `displayName`: The readable name shown in user interfaces.
* `version`: The current Component version.
* `description`: A description of the Component.
* `requiresLiberrpa`: The compatible `liberrpa` version range.
* `componentDependencies`: Direct dependencies on other Components.

Do not change the Component ID manually.

### Package name

`packageName` is the technical Python package name.

PascalCase is required:

```text
ExcelTools
SAPIntegration
DocumentProcessing
```

The package name is used for:

* the directory under `src/`;
* Python imports;
* generated Snippet aliases;
* Component package conflict detection.

Avoid changing `packageName` after the Component has been published. Changing it changes the Python import path and public API.

Two Components with the same package name cannot be used in the same Project, even when their Component IDs or display names are different.

Package-name comparison is case-insensitive on Windows.

### Display name

`displayName` is intended for user interfaces and documentation.

It may contain spaces, Chinese characters, or other readable text:

```text
Excel Tools
Excel 自动化工具
SAP Integration Toolkit
```

Changing the display name does not change:

* the Component ID;
* the Python package name;
* imports;
* generated aliases;
* dependency declarations.

Display names do not need to be unique.

## Source code

Place Component source code under:

```text
src/<ComponentPackageName>/
```

For example:

```text
src/
└── ExcelTools/
    ├── __init__.py
    ├── py.typed
    ├── Workbook.py
    ├── Worksheet.py
    └── _Validation.py
```

A Component does not have a required entry module. Organize modules according to their responsibilities.

Public module names should use PascalCase:

```text
Workbook.py
Worksheet.py
DataTable.py
```

Internal modules should start with an underscore:

```text
_Common.py
_Validation.py
_InternalTypes.py
```

The first version of LiberRPA Component Snippet generation only scans direct Python modules under the Component package. Nested packages are not treated as public Snippet modules.

## Public functions

LiberRPA treats top-level functions whose names do not start with an underscore as public AST Snippet candidates.

For example:

```python
def open_workbook(file_path: str):
    ...
```

Internal helper functions should start with an underscore:

```python
def _validate_file_path(file_path: str):
    ...
```

This naming rule helps LiberRPA distinguish intended public APIs from internal implementation details.

A function without an underscore is only an AST Snippet candidate. It is not automatically guaranteed to appear in the published Snippet catalog.

Use type annotations and docstrings for public functions. LiberRPA reads source code through static AST analysis and does not import or execute the Component while generating Snippets.

## Snippet naming

LiberRPA generates a stable module alias using:

```text
<ComponentPackageName>_<ModuleName>
```

For example:

```python
from ExcelTools import Workbook as ExcelTools_Workbook
```

An automatically generated function Snippet uses:

```text
Category: ExcelTools_Workbook
Label:    open_workbook
Prefix:   ExcelTools_Workbook.open_workbook
```

The TreeView structure therefore matches the text users type:

```text
ExcelTools_Workbook
└── open_workbook
```

```python
ExcelTools_Workbook.open_workbook(...)
```

This convention is generated automatically. Do not create custom aliases for automatically generated Component Snippets.

## AST Snippets

LiberRPA generates AST Snippets through static source analysis.

The scanner considers:

1. Direct Python modules under:
   ```text
   src/<ComponentPackageName>/
   ```
2. Modules whose file names:
   * do not start with `_`;
   * are not `__init__.py`.
3. Top-level functions whose names do not start with `_`.

AST generation is intentionally conservative.

A function may be skipped when its signature, annotations, default values, or other syntax cannot be converted into a reliable Snippet. LiberRPA prioritizes generating correct Snippets rather than attempting to recognize every possible public function.

During the first Publish Preparation, LiberRPA:

1. scans the Component source code;
2. generates `_Snippets/ast.snippets.json`;
3. creates `_Snippets/snippets.jsonc`;
4. shows the detected and skipped functions;
5. opens the Snippet files for review;
6. stops the publishing operation.

Review the generated candidates before publishing.

## `_Snippets/ast.snippets.json`

`ast.snippets.json` contains the complete current AST generation result.

It is:

* generated automatically;
* replaced when AST Snippets are regenerated;
* intended for inspection and preview;
* not intended for manual editing;
* not used as a trusted publishing input without rescanning the source code.

Do not store manual changes in this file.

## `_Snippets/snippets.jsonc`

`snippets.jsonc` is the user-maintained Snippet configuration.

It is used to:

* select which AST-generated candidates are published;
* override selected properties of generated Snippets;
* define completely handwritten Snippets.

Only selected AST candidates are included in the final published catalog.

This means a newly added public function does not silently become a published Snippet before it has been reviewed.

Handwritten Snippets are suitable for:

* multi-step templates;
* calls involving multiple functions;
* custom placeholders;
* control flow;
* exception handling;
* functions intentionally skipped by AST generation.

Keep `snippets.jsonc` under version control.

## Version

The Component version is stored in `component.json`.

Versions must follow Python PEP 440. Most Component developers only need the familiar `MAJOR.MINOR.PATCH` format:

```text
1.0.0
1.0.1
1.1.0
2.0.0
```

As a general guideline:

* Increase `PATCH` for compatible fixes.
* Increase `MINOR` for compatible new features.
* Increase `MAJOR` for incompatible changes.

A Component version committed to ComponentRepository is immutable.

The same Component ID and version cannot later be replaced with different content.

Publishing does not automatically change the version in `component.json`. Set the intended version before publishing.

## Component dependencies

Direct Component dependencies are declared in `component.json`.

Do not manually copy dependency source code into this Project.

LiberRPA Project Manager resolves exact versions and creates:

```text
components.lock.json
_Components/
```

`components.lock.json` records the exact resolved Component versions and integrity information.

`_Components/` contains the resolved Component packages expanded from Wheels in the configured ComponentRepository.

Use LiberRPA Project Manager to:

* add dependencies;
* update dependencies;
* remove dependencies;
* restore dependencies from the lock file;
* repair missing or damaged `_Components` content.

When the Component has no Component dependencies, `components.lock.json` and `_Components/` normally do not exist.

Commit `components.lock.json` to version control.

Do not commit `_Components/`, because it can be restored from the lock file and ComponentRepository.

## Python environment

LiberRPA uses one fixed Python environment instead of creating a separate environment for each Project.

A Component may use:

* the Python standard library;
* `liberrpa`;
* declared LiberRPA Components;
* third-party packages already available in the LiberRPA Python environment.

Additional third-party Python packages are not currently installed, locked, or transferred automatically by Component dependency management.

The Component developer is responsible for understanding and documenting any additional environment requirements.

This Project uses Ruff for Python linting and formatting.

Recommended usage in LiberRPA Editor:

* use the Problems panel to review Ruff diagnostics;
* use Format Document to format the current Python file;
* use Quick Fix to apply reviewed fixes.

## Managed and generated files

The following files and directories are managed by LiberRPA:

```text
_Components/
components.lock.json
_Snippets/ast.snippets.json
```

Do not manually copy, rename, replace, or delete managed Component dependency content.

`_Snippets/snippets.jsonc` is user-maintained and may be edited.

Do not add permanent handwritten packaging files such as:

```text
pyproject.toml
setup.py
```

LiberRPA generates temporary packaging configuration, builds the Wheel, and validates it inside an isolated staging directory.

Build output is not stored permanently in the Component Project.
